# Feature specifications

For larger features create `docs/features/<issue>-<name>.md` using [template](template.md).
Small fixes need issue acceptance criteria and a focused PR, not extra bureaucracy.
The spec → plan → tasks structure follows GitHub Spec Kit principles without requiring
its CLI or adding tool-specific duplicate instruction files.

Specify behavior first, reference canonical contracts/ADRs, identify approval blockers,
then list a testable plan and dependencies. Preserve measured results separately.
